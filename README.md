# Political Archive Crawler

以 PostgreSQL 保存可追溯政治公開資料的 Python 專案。目前已完成並驗證
M0 foundation 與 M1 PostgreSQL schema and evidence foundation（驗證日期：
2026-07-15）。M1 不代表已完成 crawler、真實來源 adapter 或 R1；**M0/M1
均不等於 R1**。

## Current status

### M0 acceptance（已完成）

M0 提供 Python 3.12/uv、Pydantic 設定、Typer help、loopback-only PostgreSQL
16 Compose service，以及 Ruff/mypy/pytest 基礎。最近驗證包含：`uv sync
--frozen`、CLI help、lint/format/type check/tests、`docker compose config`、
Compose healthcheck 與 `pg_isready`（2026-07-15）。

### M1 acceptance（已完成）

- SQLAlchemy 2 + psycopg typed models 與 Alembic 唯一 schema 寫入來源。
- 11 張資料表、BIGINT `GENERATED BY DEFAULT AS IDENTITY`、UTC timestamptz
  timestamps、DATE semantic dates、JSONB、封閉集合 constraints 與 query indexes。
- raw `content_hash` 與 normalized `normalized_content_hash`；raw hash 改變
  才建立 revision，raw 不同即使 normalized 相同仍保留 revision。
- content-addressed、atomic no-clobber evidence storage；DB failure 可留下
  安全 orphan，storage 不負責 DB commit。
- URL/hash dedup helpers、race-safe unique handling、crawl lifecycle/counters
  與不可覆寫的 review audit rows。
- unit tests 與獨立 `political_archive_test` PostgreSQL integration tests。

## Local PostgreSQL and health

```bash
cp .env.example .env
docker compose up -d db
docker compose ps
docker compose exec -T db pg_isready -U political_archive -d political_archive
```

Database 只綁定 `127.0.0.1`。`.env` 不可提交，範例值只適用本機開發。

## Migration workflow

以下命令將 application database 升級至目前 schema：

```bash
uv run alembic upgrade head
uv run alembic current
```

不要在保存開發資料的 database 上以 `downgrade base` 測試 migration。Migration
round trip 由 integration fixture 在獨立 `political_archive_test` database 執行，
不會 drop/清空 dev database。

M4 前不提供 `db-upgrade` CLI wrapper。Application import 不會連線、也不會
`create_all`。

## Evidence storage

```
data/source/pdf/{sha256}.pdf
data/source/html/{sha256}.html.zst
data/source/json/{sha256}.json.zst
data/normalized/markdown/{sha256}.md.zst
```

PDF 保留原始 bytes；HTML/JSON/Markdown 使用 zstd。path 只能是 storage root
下的相對安全路徑，寫入先 fsync temporary file，再以 no-clobber atomic publish
完成；相同 hash idempotent，既有內容損壞或衝突則拒絕。Artifact write 先於
每份 document 的 DB transaction，DB 失敗時允許安全 orphan，後續 cleanup
屬於 M4/M5。

## Development and tests

```bash
uv sync --frozen
uv run political-archive --help
uv run pytest tests/unit
uv run pytest tests/integration
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy src
docker compose config
```

Integration tests 只使用固定名稱 `political_archive_test`，由 fixture 建立並
執行 clean upgrade/downgrade/re-upgrade；預設只允許 loopback DB host，且永遠
不會 target 或 drop `political_archive`。若 CI 明確需要 remote DB，必須設定
`PA_ALLOW_REMOTE_TEST_DATABASE=true`，並自行承擔 remote schema 風險。正常 unit
tests 不需要 DB 或 live website。
